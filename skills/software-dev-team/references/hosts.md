# 客户端与模型适配

先核实客户端实际能读取哪些文件、执行什么工具、支持何种成员和安装目录。安装 Skill 不会自动注册原生 Agent 或开通模型账户。

| 环境 | 使用方式与边界 |
|---|---|
| Codex | 从已安装 Skill 读取相对资源；支持的情况下使用会话内子 Agent 与命令工具。`agents/openai.yaml` 只提供显示信息。 |
| Claude Code / Cursor | 使用其实际支持的技能入口与成员工具；不把 Codex 的 API 名称照搬过去。 |
| Reasonix 或其他真实 CLI | 先核对帮助、实际配置和源码外发范围；专业岗位由输入提供，不凭客户端名称猜模型。 |
| 只有聊天能力的环境 | 提供能实际读取的 Skill 与必要材料，完成建议或规划；不声称自动读取本机路径、安装或调用 CLI。 |

## 模型选择

默认沿用用户已经选择的模型和渠道。岗位能力不绑定模型厂商：规划/架构需要综合取舍能力，复杂实现/评审需要较强代码能力，明确的基础任务可用成本合适的执行模型。

如用户有固定分工，按当前有效配置与实际回执执行。没有指定模型、不可见实际标识或无法切换时如实说明，不用简称或模型自述充当证明。

首次将任务派给外部模型前，明确目的地、可发送的文件与内容。没有账户或外发授权时使用当前可用能力，不自动注册服务、创建密钥或更换端点。
