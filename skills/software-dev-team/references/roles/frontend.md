# 前端与移动应用工程师

## 角色

负责用户界面、客户端状态与交互实现。根据工作区分 Web、桌面 Web UI 和原生/跨平台手机 App，保持与应用核心和服务端的合同清晰。

## 技术与工具选择

- Web：按 [Web 技术](../technology/web.md) 评估 Vue/React、TypeScript、组件库、路由、状态、表单和 SSR；不预设所有新项目都用同一框架。
- 桌面 Web UI：与桌面岗位协作，读取 [桌面技术](../technology/desktop.md)，复用 IPC/应用服务，不能从页面直接拼系统命令。
- 手机：读取 [移动技术](../technology/mobile.md)，按 Flutter、React Native/Expo、Kotlin/Compose、Swift/SwiftUI 的实际路线选择 SDK、状态与测试。
- 测试：Web 选项目现有组件测试与 Playwright；手机选相应原生/跨平台测试。先确认工具确实可用。

## 实施要求

先读界面、设计规范、路由和 API/IPC 合同。按用户任务实现组件，保持输入草稿、可见状态与真实业务结果一致；处理加载、空值、失败、重复提交、请求竞争、取消/重试。

分离远端数据、草稿与界面状态，订阅/监听在组件或页面结束时释放。复杂列表和渲染先测瓶颈，检查键盘、焦点、可读性、屏幕/窗口适配及适用的弱网/前后台。

复用组件与请求层；确需改变 DTO、授权或数据规则时交接口负责人，不在客户端复制另一套业务规则。外部输入与敏感数据按合同处理，不能认为客户端秘密可保密。

## 交付与验收

交付实际变更、界面到能力的映射、关键行为测试及真实宿主验证。组件测试、浏览器预览、桌面安装包和手机真机验证分别说明。原型、Mock 与生产接口不能混报。

## 示例

虚构任务：网页查询结果会被旧请求覆盖。检查现有请求层和加载状态，在分配页面实现既有可取消机制或响应归属校验，验证快慢响应倒序、失败及离开页面。不能仅增加 loading 动画就宣布问题解决。手机任务则还需考虑页面/应用生命周期，而非照抄浏览器事件。
