# 预算、容量与时间

## 输入与口径

记录范围、执行者、兼任职责、有效容量、依赖、日历/时区、币种、费用口径、截止与授权。未知写 null 或待确认；未计人工成本需明确说明，不把未知当免费。不强制用户先给出精确估算。

同一个执行者承担多个 role_id 时使用相同 executor/资源 ID，不重复计容量。人类工时、agent 墙钟时长、token 量和工具等待分别记录；增加岗位数不会自动增加产能。

## 估算与预测

三点工时 O ≤ M ≤ P：乐观、最可能、悲观。PERT 期望 E = (O + 4M + P) / 6；三情景不是 P50/P90 或置信区间。先验证最高风险的一条切片，再用实际消耗校准。

成本 = Σ(工时 × 费率) + 模型/工具 + 云/CI/存储 + 其他费用 + 已约定预备金。token 费用按所选供应商当前计价单位和实际单价计算，不预置市场报价。不要在小时费率与额外费用中重复计同一项。不同币种需明确转换来源与日期。

预测总成本 EAC = 实际 AC + 剩余估算 ETC；余额 = 已批准预算 − EAC。actual_cost、remaining_cost 未知时不保证预算可行。用现有工具/计算器复核，不要求安装新的运行时。

把评审、整合、沟通、返工、工具等待与人类批准纳入计划。先排依赖再检查每个执行者每日容量；法定假期、调休和日期缓冲不能由模型猜测。日期缓冲与金额预备金分开。

## 有约束的任务卡

可选 delivery 含 executor、capacity_hours_per_day、estimate_hours、currency、cost_limit、actual_cost、remaining_cost、deadline 和 max_rework_rounds。缺失事实用 null；三点估算一起未知或都给出。日期是项目时区的 YYYY-MM-DD。

max_rework_rounds 是本次已约定的修正轮数，不作为全局固定次数。若未知则 null；执行前依据项目上限或当前任务风险约定停止点，不能无限循环。成本/日期冲突不因 task schema 合法而消失。

达到项目费用上限、接口假设失效或重复失败超限时，保存可审查产物，报告已消耗、剩余与可选方案；不自动加钱、换模型、删除验收标准或扩大权限。已有授权的独立可逆任务仍可继续。

## 两个微型演算（全为虚构）

Web：甲兼 architect/backend；接口 6h → 后端 12h；乙做前端 12h，依赖接口；丙验收 6h，依赖前后端。三人各有每日 6h 有效容量，依赖在上游完成后的下个工作日开始，总共 4 个工作日、36h。假设统一 100 CNY/h、其他费用 400、预备金 10%，成本 4,400 CNY。4,000 的上限有冲突，需明确缩减范围或调整预算；不能靠删除测试“达标”。

GUI 网络：先核实协议和目标 OS。已有设备服务时可能无需新服务端；若协议与服务端均由甲承担，必须共用容量。未知硬件、协议、费率或容量时，只提供责任划分和验证计划，不输出虚假的可运行预算。
