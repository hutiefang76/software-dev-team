# 共享规范

这是工程能力补充。用户当前要求、宿主权限及目标项目有效规则决定实际范围。

## 当前入口与协作

从目标仓的当前入口理解需求与现有能力，复用唯一有效计划。多仓任务先确定每仓职责和依赖；历史材料按项目归档规则处理，不从旧摘要继承执行授权。

角色不授予权限。仅规划的请求结束于分析与计划；实施任务在授权范围内推进。任务卡明确文件单写者与运行资源负责人，不为凑岗位拆分强依赖工作。

多人协作的记录应能独立读懂：写明工具、岗位/仓库、成员或会话 ID、记录作者；未知身份写“未知”，配合可核验的任务或运行回执。新建独立聊天需要用户明确要求。

## 工程与兼容

先核对现有实现、接口和必要测试，再做最小充分调整。沿用项目技术栈、组件、数据模型和正式构建入口，不因岗位偏好重建系统。共享业务规则保留一处真源。

API、命令、文件格式及数据库迁移考虑既有调用方。区分可逆改动与具有外部影响的数据/发布操作；按实际授权处理，不额外要求用户重复批准已明确的范围。

测试覆盖行为和有意义的失败边界；不为文本或可逆小改堆砌实现镜像测试。验证失败时保留证据，不删除门禁或改标准制造通过。

## 产品与交互

描述用户任务、前置条件、可见状态和完成条件。按需覆盖加载、空值、失败、取消、重试和恢复；小改复用现有流程。界面用普通名称，技术编号只作必要的证据。

状态取自实际业务来源，不以进度百分比、上传成功或健康响应推断目标已完成。检查适用的键盘、焦点、阅读和窗口适配行为。

## 资源、数据与外发

任务只读范围、可写范围与执行资源分别明确；共享环境由唯一负责人操作。不要外发未授权源码、凭据、日志或真实数据。外发合同同时写目的地与内容，不能只写“允许联网”。

工具拒绝或权限不足时保留边界，完成不依赖阻塞项的工作。不要换端点规避拒绝。软件包下载不等于已允许向该工具配置的所有模型发送项目资料。

## 证据与完成

分别报告建议、已修改、静态检查、测试、构建、发布、安装、业务结果和人工确认。未运行写“未执行”；失败或跳过附原因。成员完成局部任务不等于整体目标完成。

产品正式版本、依赖版本、运行环境和测试批次分别表述。配置中的模型名称是拟派发；实际工具参数、任务回执和产物才是调用依据。
