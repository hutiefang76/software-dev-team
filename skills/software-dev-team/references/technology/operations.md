# 运维按交付内容选择工具

先确定目标环境、系统/架构、网络、制品来源、资源归属、配置/秘密、数据、恢复和运行负责人。已有工具优先，不为了岗位名称新增平台。

| 工作 | 候选工具 | 适用条件与注意 |
|---|---|---|
| 构建与自动检查 | 现有 CI；GitHub Actions/GitLab CI 等 | 固定工具链、制品与可重复构建，不把 CI 成功当业务验收 |
| 单机应用交付 | 系统服务、反向代理，或 Docker/Podman + Compose | 少量服务先比较简单运行方式，处理重启、权限、持久卷和端口 |
| 多节点调度/隔离 | Kubernetes + Helm 等既有能力 | 只有真实需要才加入；处理探针、资源、网络、配置与升级 |
| 多主机一致配置 | Ansible | 幂等、清单与变更预览；SSH 身份、权限和目标核对 |
| 基础设施可重复管理 | Terraform/OpenTofu 等项目工具 | 状态、锁、plan 与成本；不直接套用未知云资源 |
| 指标、日志与追踪 | OpenTelemetry；必要时 Prometheus/Grafana 与日志系统 | 从 SLO/排错需求选最小集合，控制敏感字段、采样和存储成本 |
| 备份与恢复 | 数据库/存储官方工具与既有调度 | 保留策略、完整性、加密/权限、隔离恢复实测，不能只证明文件存在 |
| 依赖/镜像检查 | 项目现有 SCA、镜像扫描与秘密检测工具 | 区分已证实风险与误报；不把扫描输出直接当可利用漏洞 |

生产操作、持久数据、DNS/账号/证书与对外发布按当前授权处理。先轻量检查、预览与恢复条件，再做最小操作；共享环境只有明确操作者。

交付写清产品版本、制品、目标配置、操作回执、服务回读和用户业务结果。安装器、流水线、探针、登录与业务是不同层次。

工具不是全部都安装。核对实际可用能力、权限和版本，依赖不足时说明具体影响与可执行替代。

依据：[Compose](https://docs.docker.com/compose/)、[Ansible](https://docs.ansible.com/)、[OpenTelemetry](https://opentelemetry.io/docs/)。
