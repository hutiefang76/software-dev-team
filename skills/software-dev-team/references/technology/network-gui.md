# GUI 网络软件：协议、两端与 UI

先确认设备、操作系统、现有协议、网络边界、数据规模和可见行为。远端可能由设备已有服务承担，不默认新增服务端。把“离线”区分为无互联网和完全无网络。

| 责任 | 现有岗位承担方式 | 技术能力与交付 |
|---|---|---|
| 协议 | architect 定合同，backend/desktop 按边实现 | 分帧、字节序、大小上限、状态机、协商、超时、背压、取消、兼容向量 |
| 服务端 | backend；设备已有服务时只确认对接责任 | 会话/状态、鉴权、并发、幂等、流控、可观测性 |
| 客户端 | desktop | UI 与 I/O 线程隔离、IPC、生命周期、存储、安装升级、断连恢复 |
| UI | product + frontend/desktop | 连接/加载/空/失败/取消/恢复状态，键盘焦点、可访问性 |
| 测试 | qa | 畸形/截断/重复/超大消息、旧新版本、重连风暴、慢消费者、资源释放、真实 OS |
| 运维 | devops | 构建、制品、签名授权、配置、指标、恢复与回退 |

候选：类型化的受控 RPC 可评估 [gRPC](https://grpc.io/docs/what-is-grpc/introduction/)；Java 自定义协议/底层网络可评估 [Netty](https://netty.io/)。优先现有协议，不把 gRPC 当所有浏览器和设备都原生支持的传输。

客户端沿用 [桌面选型](desktop.md)：Electron 适合已有 Web 能力，需测包体与资源并核对 IPC/隔离；Tauri 需能维护 Rust 与各平台 WebView；Qt 需相应 C++/QML 和平台能力。任何性能、内存或设备兼容结论都以目标环境实测为准，版本和许可重新查官方。

交付可复核的状态机、接口、字节级向量和两端版本矩阵。重试需次数、退避与幂等语义；不凭重试承诺“恰好一次”。性能证据包含版本、环境、负载、窗口、分位延迟、错误率及资源，不用正常态演示替代故障验证。
