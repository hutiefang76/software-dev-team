# 按需技术能力

这里只给岗位关注点，实际语言、框架、版本和命令来自目标项目。按标题读取必要章节，不将这些示例当强制技术选型。

## 项目与架构

需求到验收的映射、依赖方向、模块边界、接口兼容、状态所有权、幂等、并发、取消与恢复；小改沿用现有结构。

## 前端

项目现有组件体系、类型与 API 适配、表单与草稿、异步状态、请求竞争、错误与重试、键盘与焦点；测试针对用户行为，浏览器结果和真实桌面行为分别验证。

## 后端

路由/控制器、服务与持久化边界、认证/授权、输入与错误合同、事务与并发、可观测性、幂等和兼容迁移；按实际栈选择 Java、TypeScript、Python、Go、Rust 等。

## 桌面

应用核心与界面边界、IPC、进程/文件生命周期、事件和状态回读、签名与打包、平台差异。复用共享核心，不在 GUI/CLI 各实现一套业务规则。

## 数据

数据粒度、键、重复、NULL、时区、增量边界、重跑幂等、事务、连接管理及迁移；固定基线，区分静态 SQL、隔离数据测试与真实业务结果。

## 自动化与操作系统

PowerShell/POSIX shell/Python 的实际解释器合同；argv、路径、编码、stdin、退出码、超时、取消、锁与清理。

Windows 使用字面路径和参数数组，不用 JSON 字符串替代 Shell quoting，不占用 HOME/CODEX_HOME 等系统变量。跨 Shell 删除/移动前核对绝对目标，不能把 PowerShell 枚举交给另一 Shell 拼接处理。

Linux 按目标环境核对 Shell、权限、服务管理器和进程生命周期。SSH 连通、服务健康、操作终态和业务结果分别验证；不从断连恢复推断系统重启恢复。

## 交付与安全

复用正式 CI/CD、制品与目标环境合同，固定实际版本和资产；检查部署、路由、认证、存储及用户目标。恢复方式按任务需要明确。

安全检查聚焦当前变更的信任边界、授权、秘密处理、注入、路径穿越与供应链；基于实际数据流提出修复，不把假设风险写成已利用漏洞。

## 测试

按行为选择单元、合同、集成和端到端验证。说明前置条件与环境，检查关键失败路径及回归。静态通过、产物存在、部署健康和业务通过是不同证据。
