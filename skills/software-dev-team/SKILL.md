# 软件开发虚拟团队

本目录为可独立安装的技能包。以下路径相对于本目录，不依赖开发者电脑或原始仓库。

## 先确定任务

先遵守目标项目的当前规则和用户要求，读取 [共享规范](references/shared-rules.md) 的相关条目。保持项目现有计划与工作流的唯一性。

- 清楚的小任务直接完成，简单问答无需安装运行时或启动团队。
- 需要专业能力时，从 [岗位索引](references/roles.json) 选择一个必要岗位，读取对应正文。
- 需要分工时才读 [协调者](references/roles/planner.md) 与 [协作合同](references/collaboration.md)，按独立工作量选择成员数量。
- 只加载 [技术能力](references/stacks.md) 中相关章节。角色、客户端、模型分别选择。

## 自动准备 Maestro

本次任务需要编排，或用户明确要求准备 Maestro 时，先运行：

```text
node <本技能绝对路径>/scripts/maestro-runtime.mjs ensure
```

首次自动从官方 npm 安装；以后默认每 24 小时检查并自动更新。命令只下载官方软件，不向模型服务发送源码。运行前尊重宿主的网络、软件安装及目录写入限制；遇到拒绝不换目的地重试。

根据 JSON 回执读取实际版本、上游岗位入口与资源目录。将 `version` 固定为本任务使用的版本，之后所有 Maestro 命令经以下入口执行：

```text
node <本技能绝对路径>/scripts/maestro-runtime.mjs run --version <回执版本> -- <官方子命令和参数>
```

按需读 [Maestro 适配](references/maestro.md)。读取当前安装包自带的官方路由 Skill，不照抄历史命令。已有 Session/Run 继续消费原合同，不在任务中切换版本、不另开循环。运行时更新不自动迁移项目状态。

缺少 Node.js/npm 或网络不可用时，明确运行时状态；已有缓存可继续使用。角色能力仍可用于直接处理任务，不伪称 Maestro 已运行。详情见 [运行环境](references/runtime.md)。

## 分工与回传

派发前明确目标、输入、允许读写文件、执行资源、外发目的地与内容、依赖、验收和停止条件。已有宿主合同承载这些信息时直接复用；否则使用 [任务卡](references/task-card.schema.json) 的字段，格式可为简短文字或 JSON。

成员是否可派发由当前用户授权、宿主能力及项目规则决定。优先会话内有界成员；独立聊天仅在用户要求时创建。文件单写者与共享资源负责人明确到成员，不通过角色授予额外权限。

默认使用当前会话可用的模型和工具。可按任务难度分配模型，不固定厂商、账户或版本；外部 CLI 适配见 [客户端与模型](references/hosts.md)。参数与回执确认实际调用，未验证的能力写“待核实”。

成员返回成果、位置、实际验证与未完成；协调者核对差异并整合。重要行为由独立上下文验收；无法独立验收时说明限制。分别报告静态检查、测试、构建、发布、安装和业务验收，不能用前一层替代后一层。
